# Subskrypcja Claude w runach bez człowieka

Ticket: [#42](https://github.com/jameshopecode/cohort-005-project-widelec/issues/42) (mapa [#41](https://github.com/jameshopecode/cohort-005-project-widelec/issues/41)).
Stan źródeł na 2026-11-21. Źródła to dokumentacja Claude Code, Help Center Anthropic i regulaminy Anthropic. Strony Help Center nie podają dokładnej daty aktualizacji („Updated over N weeks ago”), więc daty podaję tylko tam, gdzie strona je zawiera.

## Odpowiedź w skrócie

- **Technicznie run bez człowieka na subskrypcji jest wspierany i udokumentowany.** `claude setup-token` wydaje roczny token OAuth. Runner przekazuje go do Claude Code (`claude -p`, Agent SDK, `claude-code-action`) w zmiennej `CLAUDE_CODE_OAUTH_TOKEN`. Anthropic wprost opisuje to jako metodę „for CI pipelines and scripts where browser login isn't available” ([Authentication](https://code.claude.com/docs/en/authentication#generate-a-long-lived-token)).
- **Regulamin dopuszcza to dla własnego, indywidualnego użytku właściciela, nie dla produktu.** Consumer Terms (Pro/Max/Ultra) zakazują dostępu „through automated or non-human means, whether through a bot, script, or otherwise”, ale z wyjątkiem „where we otherwise explicitly permit it” (§3 pkt 7). Dokumentacja Claude Code wprost przewiduje token subskrypcyjny do CI i skryptów, a Help Center potwierdza, że `claude -p` i Agent SDK zalogowane planem liczą się do limitów subskrypcji. Granica przebiega przy „ordinary, individual usage”: nie wolno oferować logowania claude.ai w cudzym produkcie, przepuszczać ruchu innych osób przez swój plan ani udostępniać poświadczeń ([Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)).
- **Unieważnienie jest szybkie i samoobsługowe.** Token usuwa się ikoną kosza w claude.ai, w **Settings > Claude Code**. Ostrzejsza opcja to **Settings > Account → wyloguj wszystkie sesje**, które „immediately” wylogowuje wszędzie, łącznie z tokenami z `setup-token` ([Help Center](https://support.claude.com/en/articles/10310342-how-do-i-log-out-of-all-active-sessions)).
- **Limity są wspólne z czatem i nie przewidują osobnej puli dla runów.** Pro i Max mają okno 5-godzinne oraz limit tygodniowy, wspólne dla Claude i Claude Code. Anthropic nie publikuje limitu liczby równoległych runów: ogranicza je wspólny budżet tokenów i throttling serwera.
- **Ryzyko przy naruszeniu**: zawieszenie lub zamknięcie konta „at any time without notice” (§13), a dla Claude Code osobno: „Anthropic reserves the right to take measures to enforce these restrictions and may do so without prior notice”.

## 2. Unieważnienie

- **Pojedynczy token**: claude.ai → **Settings > Claude Code** → ikona kosza. „To remove a token and log out of Claude Code, click the trash can icon. To log out of Claude Code and stay signed in everywhere else, remove its authorization token instead.” ([Help Center](https://support.claude.com/en/articles/10310342-how-do-i-log-out-of-all-active-sessions))
- **Wszystko naraz**: **Settings > Account → Log out of all sessions**: „This action will **immediately** sign you out of your account across all devices…”, łącznie z „Claude Code, including tokens created with `setup-token` for continuous integration (CI)”. (jw.)
- **Usunięcie sekretu w git hoście tokenu nie unieważnia.** Dokumentacja mówi to wprost dla sekretów GitHub Actions: „If you delete a secret, the credential it held stays valid.” ([GitHub Actions › Uninstall](https://code.claude.com/docs/en/github-actions#uninstall))
- **Co widzi run po unieważnieniu**: w `-p` i Agent SDK błąd `Failed to authenticate: OAuth token revoked…` z kodem `authentication_failed`. Claude Code nie przełącza się na inny token: „keeps sending the value you set after a request fails with a 401”. ([Errors › OAuth token revoked or expired](https://code.claude.com/docs/en/errors#oauth-token-revoked-or-expired))
- **Opóźnienie**: Help Center używa słowa „immediately” tylko dla wylogowania wszystkich sesji. Dla kosza przy pojedynczym tokenie źródła nie podają czasu propagacji. Run zostaje odrzucony przy najbliższym żądaniu do API, a nie w połowie generowania; tak wynika z opisu błędu 401, który dotyczy kolejnego żądania. Rzeczywiste opóźnienie warto sprawdzić empirycznie przy budowie.

## 3. Limity użycia i równoległość

- **Okna**: Pro i Max mają „five-hour session limit and a weekly limit”. „These limits are **shared across Claude and Claude Code**, meaning all activity in both tools counts against the same limits.” ([Help Center: Claude Code z planem Pro/Max/Ultra](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan))
- **Plany** (ceny web):
  - Pro ok. 20 $.
  - Max 100 $: „five times the Pro plan's usage every five hours and every week” ([Max](https://support.claude.com/en/articles/11049741-what-is-the-max-plan)).
  - Ultra 200 $: „10 times the Pro plan's usage every week”, bez okna 5-godzinnego dla zweryfikowanych kont ([Ultra](https://support.claude.com/en/articles/17728952-what-is-the-ultra-plan)).
  - Dawny Max 20x to dziś Ultra.
  - Max i Ultra mają osobny tygodniowy limit na modele Fable.
- **Run = zwykłe użycie planu**: „When you're signed in with your Claude plan, the Claude Agent SDK and `claude -p` still draw from your subscription limits.” Aktualizacja z 15.06.2026 wstrzymała wcześniej zapowiedzianą zmianę rozliczania Agent SDK; od tamtej pory nic się nie zmieniło ([Help Center: Agent SDK z planem](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan), aktualizacje z 15.06 i 7.10.2026).
- **Równoległość**: Anthropic nie publikuje limitu liczby równoległych sesji ani runów na subskrypcji. Ograniczają je trzy rzeczy:
  1. wspólny budżet tokenów: „A single burst of heavy activity, such as a large workflow fanout, can exhaust the weekly allowance before the session window resets” ([Errors › session limit](https://code.claude.com/docs/en/errors#youve-hit-your-session-limit));
  2. chwilowy throttling serwera `Server is temporarily limiting requests (not your usage limit)`, ponawiany automatycznie od v2.1.199 (jw.);
  3. zastrzeżenie, że „Advertised usage limits for Pro, Max, and Ultra plans assume **ordinary, individual usage** of Claude Code and the Agent SDK” ([Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)) oraz że Anthropic może dodać „weekly and monthly caps or model and feature usage, at our discretion” ([Max](https://support.claude.com/en/articles/11049741-what-is-the-max-plan)).
- **Po wyczerpaniu limitu**: `You've hit your session limit · resets …`. Run w `-p` kończy się błędem; w trybie interaktywnym można czekać na reset. Opcjonalnie „usage credits” (płatne, po stawkach API) przez `/usage-credits`. Dla fabryki warto je zostawić wyłączone, żeby limit działał jak hamulec kosztu.
- **Miesięczne kredyty API dla Max/Ultra** (od 7.10.2026): Max 100 $/mies., Ultra 200 $/mies., bez przenoszenia na kolejny miesiąc, w podlinkowanej organizacji Claude Console ([API credits for subscribers](https://platform.claude.com/docs/en/about-claude/api-credits-for-subscribers)). Help Center mówi, że pokrywają `claude -p` i Agent SDK uruchamiane z kluczem API tej organizacji. Strona Platform w tabeli wpisuje „Claude Code: No”, ale „Claude Agent SDK: Yes”. To ważna alternatywa, ale niespójność między źródłami trzeba zweryfikować empirycznie, zanim się na niej oprze run oparty na CLI. Po wyczerpaniu kredytów „API requests stop” i nic nie obciąża planu; można też ustawić limit wydatków per workspace.

## 4. Regulamin i co grozi przy naruszeniu

- **Pro/Max/Ultra podlegają [Consumer Terms](https://www.anthropic.com/legal/consumer-terms)** (wersja z 8.10.2025). Team/Enterprise/API podlegają Commercial Terms ([Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)).
- **§3 pkt 7**: zakaz dostępu „through automated or non-human means, whether through a bot, script, or otherwise”, z wyjątkiem „when you are accessing our Services via an Anthropic API Key or **where we otherwise explicitly permit it**”. Dla Claude Code takim wyraźnym dopuszczeniem jest dokumentacja `setup-token` („For CI pipelines, scripts…”), wsparcie `claude_code_oauth_token` w oficjalnej GitHub Action oraz potwierdzenie w Help Center, że `claude -p` i Agent SDK na planie liczą się do limitów subskrypcji.
- **§2**: „You may not share your Account login information, Anthropic API key, or Account credentials with anyone else”. Token musi zostać w infrastrukturze właściciela, a runy uruchamia tylko właściciel. Zgadza się to z założeniem mapy, że tickety pisze tylko właściciel.
- **Legal and compliance › Authentication and credential use**: OAuth jest „intended exclusively for purchasers of … subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications”. Deweloperzy produktów, „including those using the Agent SDK, should use API key authentication”. Zabronione jest też „route requests through Free, Pro, Max, or Ultra plan credentials on behalf of their users” i „collect, store, or intermediate Claude.ai credentials”. Dokumentacja Agent SDK dodaje: „Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK” ([Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)).
  - Interpretacja dla tej fabryki: właściciel uruchamia **niezmodyfikowany** Claude Code na **własnej** subskrypcji, do **własnego** repo, z ticketów pisanych **przez siebie**. To mieści się w „end user signing in to the unmodified Claude Code binary with their own Claude subscription”.
  - Ryzyko rośnie, gdy runner używa Agent SDK we własnym kodzie orchestratora. Formalnie SDK podlega Commercial Terms, a dokumentacja kieruje „developers building products” na klucz API. Najbezpieczniej uruchamiać CLI (`claude -p`) albo oficjalną `claude-code-action`, a nie własny harness na SDK.
  - Drugie ryzyko to wolumen: wiele równoległych runów przez całą dobę może zostać uznane za wyjście poza „ordinary, individual usage”.
- **Sankcje**:
  - Consumer Terms §13: „We may suspend or terminate your access to the Services at any time without notice to you if” istotnie naruszysz warunki (także ze względów bezpieczeństwa lub prawnych).
  - Legal and compliance: „Anthropic reserves the right to take measures to enforce these restrictions and may do so without prior notice.”
  - Źródła nie opisują stopniowania kar. Realne skutki to odcięcie tokenu lub konta, przez co traci się też czat i Claude Code na maszynie właściciela.

## Wnioski dla projektu fabryki

1. **Runner może używać tokenu z `claude setup-token` jako jedynego sekretu Claude.** Koszt infrastruktury wynosi 0 $ ponad subskrypcję. Token ma zakres „tylko inferencja” i da się go odwołać jednym kliknięciem, więc warunek z mapy („wyciek akceptowalny przy szybkiej unieważnialności”) jest spełniony. Trzeba spisać runbook: kosz w Settings > Claude Code → `claude setup-token` → podmiana sekretu.
2. **Uruchamiać niezmodyfikowane CLI** (`claude -p` albo `anthropics/claude-code-action`), a nie własny harness na Agent SDK. To trzyma fabrykę najbliżej „ordinary use of Claude Code” i dala od zakazów dla „developers building products”.
3. **Hamulce wolumenu po stronie orchestratora.** Limit równoległych runów (np. `concurrency` w GitHub Actions), `--max-turns`, timeouty i wyłączone usage credits. Runy dzielą limit z pracą interaktywną właściciela: fabryka „zjada” jego czat i Claude Code tego samego dnia.
4. **Na runnerze nie może być `ANTHROPIC_API_KEY`**, bo wygrywa z tokenem i przełącza rozliczenie na API. Nie używać `--bare`, bo ten tryb ignoruje token.
5. **Ścieżka awaryjna, jeśli Anthropic zaostrzy zasady albo wolumen urośnie**: kredyty API z planu Max/Ultra (100/200 $ mies. w cenie planu) z kluczem w osobnym workspace ze spend limitem, albo WIF bez długoterminowego sekretu. Ta ścieżka wymaga weryfikacji, czy CLI jest pokryte (rozbieżność między źródłami w pkt 3).
6. **Token wygasa po roku**, a „Using Claude Code doesn't extend the login”. Trzeba dodać przypomnienie o rotacji. Ostrzeżenie `claude -p` na stderr (10 dni przed końcem) jest opisane dla zapisanego loginu claude.ai; dokumentacja nie mówi, czy obejmuje też `CLAUDE_CODE_OAUTH_TOKEN`, więc nie warto na nim polegać.
